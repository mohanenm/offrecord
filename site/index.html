offrecord

Redact meeting transcripts before they reach an LLM. Fully offline.

  • Offline, alwaysNo telemetry, no update checks, no downloads at run time. Every command except setup blocks network access.
  • ReversiblePlaceholders like <P1> map back to the originals through an encrypted mapping, so you can restore an LLM’s answer on your machine.
  • Modest hardwareThe rules-only tier needs Python 3.10+ and 2 GB of RAM: Raspberry Pi 4 class. No GPU, no models required.

Before and after

A real run on the synthetic sample that ships with the repo (every name, company and number is made up). Tier 0, rules only, no models.

offrecord redact samples/sales-call.txt --no-mapping

On the full 20-turn sample: 39 spans redacted, 12 review flags, and an estimated 381 → 317 tokens (17% fewer) with the default light compression, which dropped the “Mm-hmm” backchannel and merged same-speaker turns (20 → 16). Note that “timeline” was redacted too: recall comes first, and over-redaction is the preferred failure mode.

How it works

One pipeline, four stages. Every normalised character maps back to the original, so redactions land in the right place.

  1. normalize

    Plain text, WebVTT, SRT and Whisper-style JSON become one turn model. Spoken forms become canonical: “john at example dot com” → an email, “five five five…” → digits.

  2. redact

    Regex + validators (email, phone, card with Luhn, IP, URL, dates…), your deny-list with fuzzy and phonetic matching, business context (amounts, percentages, codenames, sensitive topics) and name heuristics. Optional NER and LLM tiers only ever add redactions.

  3. compress

    light (default) removes fillers, stutters and backchannel turns; medium also drops small talk and near-duplicates. Negations, decisions and numbers are never dropped, nor any placeholder.

  4. output

    Compact text with a speaker legend, or the original format. Short, consistent placeholders (<C1>, <P2>, <AMT1>) and a header carrying a random mapping id.

Install and quick start

Needs Python 3.10+. Tier 0 has no models and downloads nothing.

Install

pipx install "git+https://github.com/mohanenm/offrecord"

With the optional model tiers (NER and local LLM), then fetch the models explicitly:

pipx install "offrecord[ner,llm] @ git+https://github.com/mohanenm/offrecord"
offrecord setup models            # Tier 1
offrecord setup models --tier 2   # Tier 2

Check your machine and redact

offrecord doctor                       # Python, RAM, tiers, models, network guard
offrecord redact call.txt --no-mapping # one-way: redacted text on stdout

Reversible flow

The mapping is encrypted with a key file. Keep the key away from the mapping.

offrecord keygen                       # ~/.config/offrecord/keys/default.key
offrecord redact call.vtt -o out.txt \
    --key-file ~/.config/offrecord/keys/default.key
# ... send out.txt to an LLM, save its answer as answer.txt ...
offrecord restore answer.txt --assume-mapping \
    --mapping ~/.local/share/offrecord/mappings/<id>.ormap \
    --key-file ~/.config/offrecord/keys/default.key

LLM round trip

Copy a transcript, redact it, paste it into any chat LLM, copy the answer back, restore it.

CommandWhat it does
offrecord redact call.vtt --prompt "Summarise the decisions"Put your instruction first and tell the LLM to keep placeholders exactly as written, so its answer restores cleanly. The instruction is redacted too: “the QFA call” becomes “the <C1> call”.
offrecord pasteRedact whatever is on the clipboard, in place (accepts --prompt too).
offrecord unpasteRestore the LLM’s copied answer on the clipboard, using the most recent mapping.
offrecord initGuided setup of your deny-list (clients, codenames, people); used automatically afterwards.
offrecord denylist add "Quillfeather Analytics" --alias QFAAdd a name later, or denylist import clients.csv from a CRM export. Names are never printed back.

Tiers and hardware floors

Pick with offrecord redact --tier 0|1|2|auto (default 0; auto picks the highest tier your RAM and installed models allow). Higher tiers only ever add redactions. CPU only.

TierWhatFloor
0Rules only. No models, no downloads.Python 3.10+, 2 GB RAM (Raspberry Pi 4 class)
1NER ensemble (GLiNER small + BERT-NER, ONNX int8) + MiniLM embeddings4 GB RAM, CPU
2Phi-4-mini 3.8B (GGUF, llama.cpp) for JSON labels only; Qwen3 1.7B fallback8 GB RAM, 4+ cores (fallback: 4 GB)

Models arrive only through the explicit offrecord setup command, with pinned versions and checksums, and live outside the repo.

Accuracy

Recall is strict: a label counts only if every letter and digit in it is redacted. Precision is measured in characters. The held-out set was never tuned on; the user set (hand-written, never tuned on) is the harder, more honest number.

Recall and precision by tier on the held-out and user sets
Recall / precisionHeld-out (56 transcripts)User set (8 transcripts)
Tier 0 (rules)91.4% / 87.6%79.0% / 88.3%
Tier 1 (+ NER ensemble)94.2% / 82.7%82.8% / 83.3%
Tier 2 (+ Phi-4-mini)94.7% / 79.3%82.5% / 82.1%
Baseline: plain regexes6.4%3.6%

On the same held-out data, Microsoft Presidio with its defaults reached 37.2% recall (its email/URL recognisers reject the reserved test domains, so those categories understate it). On the user set, the weakest Tier 0 categories are topic sentences (47%), locations (44%) and percentages (59%).

All evaluation data is synthetic. Synthetic data cannot capture real speech-recognition errors, real names and their spelling variety, domain jargon, cross-talk, or the clients and codenames in your deny-list. Expect real-world recall to be lower than these numbers, and review the flagged spans.

Privacy

Promises

  • Nothing leaves the machine at run time: no telemetry, no update checks, no downloads. Every command except setup blocks network access and child processes, and fails if anything tries.
  • Transcript text is never logged or echoed; errors give positions and categories only.
  • Your deny-list config is treated as sensitive (it names clients and codenames) and is never echoed.
  • Every file offrecord writes is owner-only; outputs are atomic and never overwritten without --force.

Restore and the mapping file

  • The mapping (placeholder → original) is written only encrypted (Fernet; key from a passphrase via scrypt or from a key file via HKDF), to a private per-user store, never next to the output or the key.
  • Passphrases come from OFFRECORD_PASSPHRASE or a prompt, never the command line.
  • Output carries the mapping id; restore fails on a mismatch. For header-less LLM answers you confirm with --assume-mapping, and every placeholder is checked.
  • Ambiguous tokens are never restored. --no-mapping runs are one-way.

Full threat model: docs/security.md.

Limitations

No tool catches everything. Review the flagged spans before sharing output.

  • Tier 0 misses names that are ordinary dictionary words (“Amber”, “Art”) unless they are in your deny-list, a speaker label, or follow a cue like “my name is”. Tier 1 catches most of them.
  • Unknown organisations or products named with ordinary words are missed at Tier 0 and partly at Tier 1.
  • Higher tiers trade precision for recall and are slower (Tier 2 is roughly 15–20 s per call transcript on a laptop CPU).
  • Sensitive-topic sentences are found by keyword (layoffs, lawsuits, health conditions, “not public”…); a sensitive sentence with none of those words is missed. Pricing and renewal sentences are flagged, not redacted, by default.
  • Relative dates (“yesterday”, “next Friday”) are not redacted.
  • aggressive compression is lossy by design (it never drops turns with placeholders, numbers, decisions or questions).
  • Python cannot wipe memory: decrypted mappings and transcript text stay in process memory until garbage collected.
